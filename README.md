### Docker-compose
Основные компоненты системы
1. Веб-приложение (Web Service)
Является ядром системы, реализующим бизнес-логику приложения. При старте автоматически выполняет миграции базы данных и запускает встроенный сервер разработки Django. Сервис доступен извне через порт 8000 и взаимодействует с базой данных и Redis для обеспечения полной функциональности.

2. База данных (Database Service)
Использует PostgreSQL версии 16.3 в качестве основной СУБД. Данные сохраняются в постоянном томе, что гарантирует их сохранность при перезапусках контейнеров. Встроенная проверка здоровья (healthcheck) отслеживает доступность базы данных перед запуском зависимых сервисов.

3. Кэш-хранилище (Redis Service)
Redis версии 7 работает в роли быстрого кэша и брокера сообщений. Обеспечивает высокопроизводительное хранение временных данных и организацию очередей для фоновых задач.

4. Обработчик фоновых задач (Celery Worker)
Выделенный сервис для выполнения асинхронных операций. Использует Redis в качестве брокера сообщений и настроен на работу в режиме совместимости (solo-pool), что упрощает отладку и разработку.

5. Планировщик задач (Celery Beat)
Отвечает за запуск периодических задач по расписанию. Работает совместно с основным воркером Celery, обеспечивая выполнение запланированных операций в заданные интервалы времени.

Взаимодействие между сервисами
Система построена по принципу последовательной зависимости, где каждый компонент знает о своем месте в архитектуре:

Веб-приложение зависит от базы данных и ожидает ее готовности перед запуском

Воркер Celery требует одновременной доступности веб-приложения, базы данных и Redis

Планировщик Celery Beat активируется после запуска всех предыдущих компонентов

Такая организация гарантирует корректный порядок инициализации и стабильную работу всех частей системы.

Хранение данных
Предусмотрено два типа постоянного хранения:

Данные базы данных — сохраняются в отдельном томе, что позволяет обновлять контейнер без потери информации

Статические файлы — хранятся в специализированном томе, обеспечивая доступ к медиа-ресурсам приложения

Оба тома изолированы от файловой системы контейнеров, что повышает надежность и упрощает управление данными.

Управление конфигурацией
Все чувствительные настройки и переменные окружения вынесены в отдельный файл, что соответствует принципам безопасности и гибкости настройки. Каждый сервис имеет доступ только к необходимым ему переменным, а критически важные параметры (хост базы данных, адрес Redis) жестко заданы в конфигурации для предотвращения ошибок.

Сетевые взаимодействия
Все сервисы объединены в единую внутреннюю сеть, что обеспечивает изолированное и безопасное взаимодействие между компонентами. Внешнему миру доступен только веб-сервер через порт 8000, остальные сервисы остаются скрытыми за внутренней сетевой инфраструктурой.

Процесс запуска
При инициализации системы соблюдается строгая последовательность:

Запускается база данных с проверкой готовности

Активируется Redis для обеспечения кэширования и очередей

Запускается веб-приложение с выполнением миграций

Инициализируется воркер Celery для фоновых задач

Запускается планировщик для периодических операций

Такая поэтапная стратегия обеспечивает стабильность и предсказуемость работы всей системы.

Особенности архитектуры
Масштабируемость — каждый сервис может быть независимо масштабирован

Отказоустойчивость — изоляция компонентов предотвращает каскадные сбои
